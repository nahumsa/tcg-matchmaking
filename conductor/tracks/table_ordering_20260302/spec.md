# Specification: Table Ordering by Points

## Overview
This track introduces table numbering and ordering for matches in a Swiss tournament. The top match (Table 1) should always consist of the players with the highest points. Table numbering will be assigned statically during pairing generation.

## Functional Requirements
- **Match Table Assignment:** Every match generated by the pairing engine must be assigned a unique table number (starting from 1).
- **Point-Based Ordering:** Matches must be sorted such that Table 1 contains the players with the highest combined points.
- **Tie-breaking:** When players have equal points, existing tournament tie-breakers (e.g., OMW%) should be used to determine the relative order.
- **Frontend Display:** The Table Number must be clearly visible in the match list on the Participant and Admin views.
- **API Updates:** The match schema must be updated to include a `table_number` field.

## Non-Functional Requirements
- **Deterministic Ordering:** Table assignment should be consistent and reproducible for the same set of pairings and standings.
- **Performance:** Sorting matches by points and tie-breakers must not significantly delay the pairing generation process.

## Acceptance Criteria
- [ ] Backend: Match model includes `table_number`.
- [ ] Backend: Pairing logic sorts matches by points/tie-breakers and assigns table numbers.
- [ ] API: Match response includes `table_number`.
- [ ] Frontend: Match cards or list items display the table number prominently.
- [ ] Verification: In a multi-round tournament, the match with the highest-ranked players is assigned Table 1.

## Out of Scope
- Manual table re-assignment by administrators.
- Support for multiple physical rooms or zones.
